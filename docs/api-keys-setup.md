# API キーの取得と設定手順

coupon-collector を実データで動かすために必要な、**API キーの取得** と **GitHub Secrets への登録** の手順書です。

- **対象読者**: このツールをこれから初めて動かす運用担当者(API や GitHub Secrets の経験は不要)
- **所要時間**: 2 サービス合わせておよそ 15〜30 分(メール確認の待ち時間を含む)
- **関連ドキュメント**: ツール全体の使い方・出力形式・アーキテクチャは [docs/coupon-collector.md](coupon-collector.md) を参照してください。この手順書はキーの取得と設定のみを扱います。

> **この手順書の書き方について**
> 環境変数名・コマンド・ログの文言はリポジトリの実コードで確認したものです。一方、各サービスの登録画面の文言・ボタン名・利用規約の具体的な条文・レートリミットの数値は変更される可能性があり、コードからは確認できません。該当箇所には「公式サイトで最新の情報を確認してください」と明記しています。画面の見た目が本書と異なる場合は、**公式サイトの表示を正としてください**。

## 概要 — 何を用意するのか

必要なキーは **2 種類だけ**です。どちらも **無料**で、登録手続きのみで取得できます(審査・費用・クレジットカード登録は不要です。ただし登録要件は変更されうるため、最新は各公式サイトで確認してください)。

| # | サービス | 取得するもの | 設定する環境変数 / Secret 名 | 登録に必要なもの |
| --- | --- | --- | --- | --- |
| 1 | ホットペッパーグルメ API(リクルート Web サービス) | API キー | `HOTPEPPER_API_KEY` | メールアドレス |
| 2 | 楽天ウェブサービス | アプリ ID(applicationId) | `RAKUTEN_APP_ID` | 楽天会員アカウント |

### 重要: キーは「必須」ではありません

coupon-collector は **キーが片方だけでも、まったく無くても正常に動作します**。

- キーが未設定のソースは**エラーにならず、ログを残してスキップ**されます(`coupon_collector/collector.py` の `collect()` の仕様)
- キーが 1 つも無い状態でも `demo` ソース(静的サンプル 4 件)だけが動き、出力ファイルは正しく生成されます
- したがって「まず動かしてみる → 後からキーを足す」という進め方で問題ありません

```
キーなし           → demo のみ収集(動作確認用)
HOTPEPPER のみ設定 → demo + hotpepper
RAKUTEN のみ設定   → demo + rakuten
両方設定           → demo + hotpepper + rakuten(フル稼働)
```

### 取得したキーをどこに置くか

| 実行する場所 | 置き場所 |
| --- | --- |
| 自分の PC(手動実行) | シェルの環境変数(`export`) |
| GitHub Actions(定期実行) | リポジトリの Secrets |

どちらの場合も、**キーの文字列をファイルに書いてコミットすることは絶対にしないでください**。詳細は[セキュリティ上の注意](#セキュリティ上の注意)を参照してください。

## 手順 1: ホットペッパーグルメ API のキーを取得する

登録先: **リクルート Web サービス** https://webservice.recruit.co.jp/

メールアドレスを登録すると API キーが発行される方式です。楽天と違い、事前のアカウント作成やアプリ登録は不要です。

### 手順

1. ブラウザで https://webservice.recruit.co.jp/ を開きます。
2. API キーの新規登録(利用登録)ページへ進みます。
   トップページから「API キー発行」「利用登録」といった趣旨のリンクをたどります。
   *リンク名・導線は変更される場合があります。見つからない場合は公式サイト内の案内を確認してください。*
3. 利用規約を確認し、同意します。
   **ここで規約に目を通してください。** 取得したデータの利用範囲やクレジット表記の義務が記載されています([利用規約とクレジット表記](#利用規約とクレジット表記)参照)。
4. 受信可能な**メールアドレス**を入力して送信します。
   業務利用のため、個人アドレスではなくチームで共有できるアドレスの利用を推奨します(退職・異動時にキーの管理者が不明にならないようにするため)。
5. 入力したアドレス宛に**確認メール**が届きます。メール内のリンクを開いて登録を完了します。
   数分待っても届かない場合は迷惑メールフォルダを確認してください。
6. **API キーが即時発行されます。** 画面またはメールに表示される英数字の文字列が API キーです。

### 取得したキーの扱い

- この文字列を、環境変数 **`HOTPEPPER_API_KEY`** および GitHub Secret **`HOTPEPPER_API_KEY`** に設定します。
- コードでは `coupon_collector/sources/hotpepper.py` がこの環境変数を読み、API のリクエストパラメータ `key` として送信します。
- キーはパスワードと同等の秘密情報です。メール本文をそのまま Slack や Issue に転載しないでください。

### 補足: 検索対象エリアの変更(任意)

`hotpepper` ソースはデフォルトで大エリアコード `Z011`(東京)を検索します。変更したい場合は、キーとは別に環境変数 `HOTPEPPER_LARGE_AREA` を設定します(任意。未設定なら `Z011`)。エリアコードの一覧は公式 API リファレンスのマスタ API で確認できます。

## 手順 2: 楽天ウェブサービスのアプリ ID を取得する

登録先: **楽天ウェブサービス** https://webservice.rakuten.co.jp/

こちらは「楽天会員としてログインし、アプリを 1 つ登録すると、そのアプリに対して ID が発行される」方式です。

### 手順

1. ブラウザで https://webservice.rakuten.co.jp/ を開きます。
2. **楽天会員アカウントでログイン**します。アカウントを持っていない場合は、先に楽天会員登録(無料)を行ってください。
3. アプリ登録(アプリ ID 発行)のページへ進みます。
   「アプリ ID 発行」「アプリ情報の登録」といった趣旨のメニューです。
   *メニュー名・導線は変更される場合があります。見つからない場合は公式サイト内の案内を確認してください。*
4. 利用規約を確認し、同意します。
5. アプリ情報を入力します。入力例:

   | 入力項目 | 入力例 | 補足 |
   | --- | --- | --- |
   | アプリ名 | `coupon-collector` | 自分が識別できる名前であれば任意。日本語でも可 |
   | アプリ URL | `https://github.com/tomato1122/MyCompany` | 公開 Web サイトがない場合はこのリポジトリの URL で構いません |

   *入力項目の名称・必須/任意の区分は変更される場合があります。実際のフォームの表示に従ってください。*
6. 登録すると **アプリ ID(applicationId)** が発行されます。数字列で表示されます。

### 「アプリシークレット」について

アプリ登録時に **アプリ ID とあわせて「アプリシークレット」が表示される場合がありますが、本ツールでは使用しません。**

- `coupon_collector/sources/rakuten.py` が読み込む環境変数は `RAKUTEN_APP_ID`(と任意の `RAKUTEN_KEYWORD`)のみで、API に送るパラメータも `applicationId` だけです。
- リポジトリ全体を検索してもシークレットやアフィリエイト ID を参照している箇所はありません。
- したがって **アプリシークレットは環境変数にも GitHub Secrets にも登録しないでください。** 不要な秘密情報を配置しないことが安全です。

### 取得した ID の扱い

- 発行されたアプリ ID を、環境変数 **`RAKUTEN_APP_ID`** および GitHub Secret **`RAKUTEN_APP_ID`** に設定します。
- アプリ ID はリクエスト URL に含まれるため厳密には秘匿性が低い値ですが、他者に使われると自分の利用枠を消費されるため、**公開しない扱い**にしてください。

### 補足: 検索キーワードの変更(任意)

`rakuten` ソースはデフォルトでキーワード「クーポン」を検索します。変更したい場合は環境変数 `RAKUTEN_KEYWORD` を設定します(任意。未設定なら「クーポン」)。

## 手順 3: GitHub Secrets に登録する

GitHub Actions での定期実行にキーを渡すための設定です。ローカル実行しかしない場合はこの手順を飛ばして[手順 4](#手順-4-ローカルで動作確認する)へ進んでください。

> **前提**: この操作にはリポジトリの管理者権限(Settings タブが見える権限)が必要です。タブが見えない場合はリポジトリ管理者に依頼してください。

### 手順

1. ブラウザでリポジトリのページ https://github.com/tomato1122/MyCompany を開きます。
2. 上部のタブから **Settings** を開きます。
3. 左サイドバーの **Secrets and variables** を展開し、**Actions** を選択します。
4. **New repository secret** ボタンをクリックします。
5. **Name** と **Secret**(値)を入力し、**Add secret** で保存します。登録するのは次の 2 件です。

   | Name(この文字列を正確に入力) | Secret(値) | 取得元 |
   | --- | --- | --- |
   | `HOTPEPPER_API_KEY` | 手順 1 で発行された API キー | リクルート Web サービス |
   | `RAKUTEN_APP_ID` | 手順 2 で発行されたアプリ ID | 楽天ウェブサービス |

6. 2 件目も同様に **New repository secret** から登録します。

### 登録時の注意

- **Name は大文字・アンダースコアまで完全一致させてください。** コードが読む環境変数名と 1 文字でも違うと、そのソースは「未設定」と判定されてスキップされます(例: `HOTPEPPER_APIKEY`、`RAKUTEN_APPID` は誤り)。
- 値をコピペする際、**前後の空白や改行が混入しないよう**注意してください。混入すると API 側でキー不正と判定されることがあります。
- 保存後、値を画面で再確認することはできません(GitHub の仕様)。値を忘れた場合は各サービスで確認し直すか、再発行します。
- 片方だけ登録しても構いません。未登録のソースがスキップされるだけで、ワークフローは失敗しません。

### ワークフロー側での受け渡しについて

登録した Secrets は、ワークフロー定義で同名の環境変数としてジョブに渡す必要があります。

> **要確認**: 本ブランチの時点でリポジトリに GitHub Actions のワークフローファイルは含まれていません(`.github/` ディレクトリが存在しません)。Secrets を登録しただけでは自動実行は始まりません。ワークフローの追加後、`env:` での受け渡しが正しく記述されているかを確認してください。詳細は [docs/coupon-collector.md の「定期実行(GitHub Actions)」](coupon-collector.md#定期実行github-actions)を参照してください。

## 手順 4: ローカルで動作確認する

キーを GitHub に登録する前後どちらでも構いませんが、**まず手元で正しく動くことを確認する**ことを推奨します。

### 準備(初回のみ)

```console
$ cd MyCompany
$ python -m venv .venv
$ source .venv/bin/activate
$ pip install -r requirements.txt
```

### パターン A: キーなしで動作確認する(demo のみ)

キーの取得を待たずに、パイプライン全体が動くことを先に確認できます。

```console
$ python -m coupon_collector --source demo
```

`demo` ソースはサンプル 4 件を生成し、そのうち 1 件は意図的に期限切れのため、**「4 件生成 → 3 件保存」になるのが正常**です。

### パターン B: キーを設定して実データを収集する

取得したキーを環境変数に設定してから実行します。`--verbose`(`-v`)を付けると DEBUG ログ(HTTP リトライの詳細など)も出るため、初回の確認に向いています。

```console
$ export HOTPEPPER_API_KEY="ここに手順1で取得したAPIキー"
$ export RAKUTEN_APP_ID="ここに手順2で取得したアプリID"
$ python -m coupon_collector --verbose
```

片方だけ確認したい場合は、そのソースだけを指定します。

```console
$ export HOTPEPPER_API_KEY="ここに手順1で取得したAPIキー"
$ python -m coupon_collector --source hotpepper --verbose
```

### 実行前に知っておくこと

- `export` はそのシェルを閉じると消えます。ターミナルを開き直したら再度 `export` が必要です。
- **`export` した内容が履歴に残ります。** 共有マシンで作業した場合は `history -c` などで履歴を消すか、後述の `.env` 方式(git 管理外)を検討してください。
- 実行すると `data/coupons.json` / `data/coupons.csv` が更新されます。リポジトリの `data/` を汚したくない場合は `--output-dir` で別の場所へ出力してください。

  ```console
  $ python -m coupon_collector --output-dir /tmp/coupon-test --verbose
  ```

## 手順 5: 設定できているかログで確認する

キーが効いているかどうかは、**実行ログの文言**で判別できます。以下はコード(`coupon_collector/collector.py` および各ソース)で出力が確認されている文言です。

### 判別表

| ログに出る文言 | 意味 | 対応 |
| --- | --- | --- |
| `ソース 'hotpepper' はAPIキー等が未設定のためスキップします` | 環境変数 `HOTPEPPER_API_KEY` が**未設定または空文字**。エラーではなく正常動作 | 実データが必要なら手順 1・4 を見直す |
| `ソース 'rakuten' はAPIキー等が未設定のためスキップします` | 環境変数 `RAKUTEN_APP_ID` が**未設定または空文字** | 実データが必要なら手順 2・4 を見直す |
| `ソース 'hotpepper' から取得を開始` | キーが**認識されている**(値の正しさはこの時点では未検証) | 正常。続くログを確認する |
| `hotpepper: クーポン付き店舗 N 件を取得` | ホットペッパーからの取得に**成功** | 設定完了 |
| `rakuten: クーポン/セール対象商品 N 件を取得` | 楽天からの取得に**成功** | 設定完了 |
| `ホットペッパーAPIエラー: ...` / `楽天APIエラー: ...` | キーは設定されているが、API 側がエラーを返した(キーの値が不正、パラメータ不正など) | キーの値を確認する。詳細は[トラブルシューティング](#トラブルシューティング) |
| `ソース 'hotpepper' の取得に失敗したためスキップします` | 通信エラーや API エラーで取得できなかった。**他のソースは続行**する | 直前のログ・スタックトレースで原因を確認する |

**ポイント**: 「未設定のためスキップ」と「取得に失敗したためスキップ」は原因がまったく違います。前者は**キーが届いていない**(名前の typo、export 忘れ、Secrets 未登録)、後者は**キーは届いているが値か通信に問題がある**という意味です。

### 実際のログ例: キーが 1 つも設定されていない場合

```console
$ python -m coupon_collector
2026-08-21 09:59:01,117 INFO    coupon_collector.collector: ソース 'demo' から取得を開始
2026-08-21 09:59:01,118 INFO    coupon_collector.sources.demo: demo: サンプルクーポン 4 件を生成(うち1件は期限切れ)
2026-08-21 09:59:01,118 INFO    coupon_collector.collector: ソース 'demo': 3 件追加 (重複 0 件・期限切れ 1 件を除外)
2026-08-21 09:59:01,118 INFO    coupon_collector.collector: ソース 'hotpepper' はAPIキー等が未設定のためスキップします
2026-08-21 09:59:01,118 INFO    coupon_collector.collector: ソース 'rakuten' はAPIキー等が未設定のためスキップします
2026-08-21 09:59:01,118 INFO    coupon_collector.collector: 収集完了: 合計 3 件
```

`hotpepper` と `rakuten` の行に「未設定のためスキップします」が出ています。この状態から、キーを設定した後に同じコマンドを実行し、該当行が **`ソース 'hotpepper' から取得を開始`** に変わっていれば設定成功です。

### GitHub Actions 側での確認方法

1. リポジトリの **Actions** タブを開きます。
2. 対象のワークフロー実行を選び、ジョブのログを展開します。
3. 上の判別表と同じ文言を探します。「未設定のためスキップします」が出ていれば、Secrets 名の綴りかワークフローの `env:` 記述を見直します。

## セキュリティ上の注意

取得したキーはパスワードと同等の秘密情報として扱ってください。

### やってはいけないこと

- **コードや設定ファイルにキーを直接書かない。** ソースコード、`README.md`、ワークフローの YAML に値をベタ書きしないでください。
- **Issue・PR コメント・コミットメッセージに貼らない。** 「動かないので見てください」とログを貼る際、キーが含まれていないか必ず確認してください。特にホットペッパー API はキーが**リクエスト URL に含まれる**ため、エラーログや `--verbose` の出力にキーが平文で現れることがあります(HTTP リトライの警告ログは URL 全体を出力します)。**ログを共有する前に、キーの部分を必ず伏せ字に置き換えてください。**
- **スクリーンショットに写り込ませない。** 画面共有・スクショにも同じ注意が必要です。
- **チャットに平文で流さない。** 共有が必要な場合はパスワードマネージャなど適切な手段を使ってください。

### 推奨する扱い方

- ローカル実行では `export` で環境変数として渡す(このリポジトリでは `.env` ファイルを読み込む仕組みは実装されていません。自分で `.env` を使う場合は必ず `.gitignore` に追加してください)。
- GitHub Actions では Secrets のみを使う。Secrets の値はログ上で自動的にマスクされます。
- 業務用の共有メールアドレス・共有アカウントで登録し、担当者の異動でキーの管理者が不明にならないようにする。

### 誤ってコミット・公開してしまった場合

**git の履歴を消すだけでは不十分です。** 公開された時点でキーは漏洩したものとして扱い、**必ず各サービスで再発行(ローテーション)してください。**

1. **各サービスでキーを再発行する**
   - ホットペッパー: リクルート Web サービスのサイトから再発行・無効化の手続きを行います。手順は公式サイトの案内を確認してください。
   - 楽天: 楽天ウェブサービスの管理画面でアプリの削除・再登録、または ID の再発行を行います。手順は公式サイトの案内を確認してください。
   - *再発行・無効化の具体的な操作方法はコードからは確認できません。公式サイトで最新の手順を確認してください。*
2. **GitHub Secrets を新しい値に更新する**(手順 3 と同じ画面で既存の Secret を Update します)
3. **ローカルの環境変数も新しい値に置き換える**
4. **古いキーが無効になったことを確認する**(古いキーで実行し、API エラーになれば無効化済み)
5. 公開範囲によっては、リポジトリ管理者・セキュリティ担当へ報告してください。

## トラブルシューティング

| 症状 | 考えられる原因 | 対処 |
| --- | --- | --- |
| キーを設定したのに `...はAPIキー等が未設定のためスキップします` が出る | **環境変数名の typo**(`HOTPEPPER_APIKEY`、`RAKUTEN_APPID`、小文字など) | `echo $HOTPEPPER_API_KEY` / `echo $RAKUTEN_APP_ID` で値が表示されるか確認する。名前は完全一致が必要 |
| 同上 | `export` を付け忘れた(`HOTPEPPER_API_KEY=xxx` だけでは子プロセスに渡らない) | `export HOTPEPPER_API_KEY="..."` と書き直す |
| 同上 | ターミナルを開き直して `export` が消えた | 同じシェルで再度 `export` する |
| 同上 | 値が空文字になっている(コピペ失敗) | コードは値の有無だけを見るため、空文字は未設定と同じ扱い。値を再設定する |
| GitHub Actions でのみ `...未設定のためスキップします` が出る | **Secrets がワークフローに渡っていない** | ワークフロー定義の `env:` に `HOTPEPPER_API_KEY: ${{ secrets.HOTPEPPER_API_KEY }}` のような記述があるか確認する。Secrets 登録だけでは自動では渡りません |
| 同上 | Secret の Name の綴り違い | Settings → Secrets and variables → Actions で Name を確認する(値は再表示できないが Name は確認できる) |
| 同上 | fork からの PR で実行している | fork 由来のワークフローには Secrets が渡らない GitHub の仕様。詳細は GitHub の公式ドキュメントを確認してください |
| `ホットペッパーAPIエラー: ...` が出る | キーの値が誤っている、前後に空白・改行が混入している | キーを再コピーして設定し直す。それでも解消しなければ再発行を検討する |
| `楽天APIエラー: ...` が出る | アプリ ID の値が誤っている、アプリが削除済み | 楽天ウェブサービスの管理画面でアプリ ID を再確認する |
| 同上 | リクエスト上限に達した可能性 | しばらく待ってから再実行する。上限値は公式ドキュメントで確認してください |
| キーがいつの間にか使えなくなった | 登録内容の失効・アプリ削除など | 各サービスの管理画面で状態を確認し、必要なら再登録・再発行する。**有効期限の有無や失効条件はコードからは確認できないため、公式サイトで確認してください** |
| `HTTP取得に失敗 (..., 試行 1/3)` の警告が繰り返される | ネットワーク側の問題、プロキシ、API 側の一時障害 | 最大 3 試行(初回+リトライ 2 回)後に該当ソースだけスキップされる。`--verbose` で詳細を確認する |
| `未知のソース名: ...`(終了コード 2) | `--source` の指定ミス | `python -m coupon_collector --help` で候補(`demo`, `hotpepper`, `rakuten`)を確認する |
| 取得件数が 0 件になる | 検索条件に合致するデータが無い(エリアやキーワードの指定次第) | `HOTPEPPER_LARGE_AREA` / `RAKUTEN_KEYWORD` を変えて試す |

解決しない場合は、**キーの文字列を伏せた上で**実行ログを添えて開発担当に相談してください。
